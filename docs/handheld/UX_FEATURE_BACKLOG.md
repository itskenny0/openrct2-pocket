# Proposed UX features

These are proposals, not verified defects or implemented capabilities. Preserve
native validation, accounting and save compatibility in any future implementation.

- Connected polylines or explicit corner routing after the current straight Line
  mode; never silently infer a diagonal route or unsupported slopes.
- A native multi-action transaction/undo mechanism, if designed and validated in
  the engine. The current sequential build review explicitly offers no atomicity.
- Optional textured multi-tile ghost previews, only if they can avoid provisional
  map mutation interfering with real path queries/conversions/connectivity.
- Larger selections or time-sliced construction only after Brick profiling and
  a clearly communicated progress/cancellation policy.
- Bulk path removal with explicit native per-tile refund and failure review.

The recommended separate management milestone remains finances, research,
marketing and remaining park management, using actionable native summaries and
consistent focus/return behavior. Do not mix that redesign into path construction.
